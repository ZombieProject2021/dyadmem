# Почему ИИ (Gemini) может удалять старый функционал?

После анализа кода проекта Dyad и системных инструкций для ИИ, я выявил несколько причин, по которым Gemini или любая другая модель может затирать существующий код при добавлении нового.

## 1. Инструкция "Write the entire file" (Писать файл целиком)
В системном промпте (`src/prompts/system_prompt.ts`, строка 312) есть жесткое правило:
> **"do NOT be lazy and ALWAYS write the entire file. It needs to be a complete file."**

Когда ИИ получает задачу добавить новую кнопку или функцию, он обязан переписать весь файл целиком. Если модель "забывает" часть старого кода в процессе генерации нового (что часто случается с длинными файлами), старый функционал просто исчезает, так как Dyad заменяет старый файл новым.

## 2. Ограничение контекста и "лень" моделей
Модели ИИ (включая Gemini) имеют ограничение на длину ответа. Если файл большой, а ИИ нужно добавить много нового кода, он может начать сокращать "неважные" (по его мнению) части старого кода, заменяя их комментариями вроде `// ... rest of the code`. Однако Dyad требует **полный** код, и такие сокращения приводят к поломке приложения.

## 3. Использование тега `<dyad-write>` вместо `<dyad-search-replace>`
В проекте есть два способа изменения кода:
- `<dyad-write>`: Полностью перезаписывает файл.
- `<dyad-search-replace>`: Делает точечные изменения (surgical edits).

Если ИИ по умолчанию использует `<dyad-write>`, риск потери данных максимален. В коде Dyad есть поддержка "Turbo Edits V2" (точечные правки), но она может быть отключена в настройках или ИИ может предпочитать полную перезапись для "надежности".

## 4. Конфликт инструкций
В промпте есть два противоречивых правила:
1. "Only make changes that were directly requested by the user. Everything else in the files must stay exactly as it was." (Делать только запрошенные изменения).
2. "ALWAYS write the entire file." (ВСЕГДА писать файл целиком).

Для ИИ это сложная задача: он должен идеально скопировать старый код и вставить в него новый. Любая ошибка в копировании приводит к удалению функционала.

# Как это исправить?

### Рекомендация 1: Использовать точечные правки
Нужно убедиться, что в настройках включен режим **Turbo Edits V2**. Это заставит ИИ использовать `<dyad-search-replace>`, который меняет только нужные строки, не трогая остальной файл.

### Рекомендация 2: Разделение на компоненты
В промпте есть правило: **"Aim for components that are 100 lines of code or less"**. Если ваши файлы становятся слишком большими, ИИ начинает ошибаться. Разделяйте код на маленькие файлы — так ИИ будет проще их перезаписывать целиком без ошибок.

### Рекомендация 3: Явное указание в чате
При запросе к ИИ добавляйте фразу:
> "Добавь [новый функционал], сохранив при этом весь текущий код и логику. Не удаляй ничего существующего."

### Рекомендация 4: Использование AI_RULES.md
Вы можете создать файл `AI_RULES.md` в корне вашего проекта и добавить туда правило:
> "Никогда не удаляй существующий функционал при добавлении нового. Если файл слишком большой для полной перезаписи, используй точечные правки или предложи разделить файл на части."
